# 合作与报价策略（内部，勿外发）

日期：2026-10-05

**本文只给你自己看。** 里面有成本拆分、人天单价和分成的谈判空间，不要直接发给天俪。给天俪的报价只提供总价和分阶段金额，见第四节。

## 一、开发费用估算

### 1. 结论

| 范围 | 工作量 | 费用（按 ¥1,800/人天） | 合理区间 |
| --- | --- | --- | --- |
| 一期基础（现有需求 + 流程缺陷修复 + 最小 P0 经营补充） | 约 685 人天 | 约 ¥125 万 | ¥90–200 万 |
| 运营工具和数据补充（渠道、埋点、用户筛选、口径、只读副本和汇总等，已扣除和 P0 重叠的部分） | 约 80–110 人天（含测试和管理） | 约 ¥15–20 万 | — |
| **一期合计** | **约 780 人天** | **约 ¥140 万** | **¥100–240 万** |
| 商城（如果进一期） | 约 125 人天 | 约 ¥22 万 | ¥18–32 万 |

属于预算级估算，范围冻结、团队确定后可以收窄到 ±15%。区间宽主要差在三点：团队形式和所在城市的人力价格、范围会不会继续变大、支付分账联调是否顺利。

### 2. 一期基础的拆分（按后端规划 M1–M5）

| 阶段 | 内容 | 前端 | 后端 | 小计（人天） |
| --- | --- | --- | --- | --- |
| M1 基础与组织 | 登录、角色、门店数据隔离、审计；门店、技师、项目价格、规则版本；排班请假；附件 | 25 | 40 | 65 |
| M2 预约与收款 | 用户下单流程、服务端报价、时段占用和并发控制、支付、派单轮、后台工作台 | 40 | 50 | 90 |
| M3 履约与异常 | 改约改派、加钟、开始和完成、取消扣费、请假影响、售后和中止、求助值班升级、履约事实与安全离开、技师端 | 45 | 55 | 100 |
| M4 资金与配套 | 分账、完结、回退、对账、追偿；分销与提现；技师提成；评价、处罚、限制下单；发票红冲；生命周期 | 40 | 70 | 110 |
| P0 经营补充 | 店内忙碌、服务交接记录、回访、统一事项工作台、独立服务准入、门店看板 | 30 | 30 | 60 |
| **开发小计** | | **180** | **245** | **425** |
| UI 视觉设计 | 已有原型，只出视觉稿和组件规范 | | | 30 |
| 测试 | 功能、回归，以及资金对账和并发两项专项，约为开发量的 30% | | | 130 |
| 产品与项目管理 | 约为开发量的 15% | | | 65 |
| M5 联调与上线 | 真实支付和供应商接入、真机测试、部署、备份恢复演练、试点支持 | | | 35 |
| **合计** | | | | **约 685** |

风险最高的是 M4 资金部分：分账、回退、对账、追偿、提现都要处理重复通知、乱序和失败重试，测试不能省。

### 3. 团队和工期

- **建议团队约 10 人**：产品 1、UI 0.5、小程序前端 2、后台前端 1–2、后端 3–4、测试 2、项目经理兼架构 1。
- **工期**：一期基础 4–5 个月到试点；加上运营和数据补充，大约多 2 周；如果商城进一期，再加 3–4 周。
- 微信支付服务商申请、门店进件、小程序类目审核要和开发同时启动，否则会卡在最后一步。

### 4. 三种做法对比（按一期合计约 780 人天）

| 做法 | 人天单价 | 工作量 | 费用 | 适合 |
| --- | --- | --- | --- | --- |
| 小团队 + AI 辅助开发 | 约 ¥1,500 | 减少约 15%（约 660 人天） | 约 ¥100 万 | 有懂行的技术负责人把关 |
| 中等外包公司（中位） | 约 ¥1,800 | 约 780 人天 | 约 ¥140 万 | 大多数情况 |
| 一线城市正规外包 | 约 ¥2,500 | 加 20% 范围风险（约 940 人天） | 约 ¥235 万 | 要求合同保障和长期维护 |

AI 辅助能省编码时间，但支付联调、测试、真机验证、审核和运维压缩不了多少，所以只按少 15% 估。现有原型是本地演示，不能直接当生产代码用，省下的是产品和设计的工作量（已计入，UI 只估 30 人天）。

### 5. 开发费以外每年要花的钱

| 项目 | 估算 |
| --- | --- |
| 运维和小迭代 | 开发费的 15–20%，约每年 ¥21–28 万 |
| 云资源 | 试点规模（2 核 4G 应用 + 独立数据库 + 对象存储），粗估每年几万元，以实际报价为准 |
| 第三方按量付费 | 短信、虚拟号码、外呼、实名和人脸核验、地图，按预计日单量询价 |
| 运营人员 | 集团客服、调度、安全值班，不属于开发费，但没有这些人系统跑不起来 |

### 6. 想压低费用可以这样做

1. **商城不进一期**：省 ¥20–30 万和 3–4 周。
2. **部分功能先人工**：发票门店线下开、分销佣金按月人工发放、评价申诉人工处理，可省 60–80 人天。
3. **按 M1–M5 分阶段签合同、分阶段付款**，每个阶段用 09 的验收用例验收。
4. **范围冻结后再报固定总价**，现在报价会带上不小的风险溢价。

## 二、合作共赢

### 1. 你凭什么长期合作

| 你能持续提供的 | 对天俪的价值 |
| --- | --- |
| 系统迭代 | 二期、三期的会员、企业客户、星级、商城、体态评估都要接着做 |
| 上线和平台能力 | 小程序审核、支付分账、第三方服务的对接和维护 |
| 运营和增长 | 复购、私域、渠道、数据分析，天俪最缺的能力 |
| 经营数据 | 门店看板、技师质量、培训效果回流 |
| 复制能力 | 新城市、新门店快速接入 |

### 2. 四种合作模式

| 模式 | 收入结构 | 风险和收益 | 适合阶段 |
| --- | --- | --- | --- |
| A. 常规外包 + 年服务费 | 开发费约 ¥140 万 + 每年开发费的 15–20% | 风险低，收益封顶 | 天俪不想绑太深时 |
| **B. 降低首款 + 按单分成**（推荐起步） | 开发费按正常报价的 65–70% 收（约 ¥90–100 万）+ 基础服务费约每年 ¥10 万 + 每单技术服务费（比如 ¥3，签 3–5 年，随单量阶梯下降） | 先垫一部分成本，单量做起来回报更高 | 试点期开始 |
| C. 承接运营，按增量分成 | 基础运营费 + 超过基线部分的分成 | 收益最大，需要运营团队 | 试点跑通后 |
| D. 合资或技术入股 | 成立数字公司，平台和数据产品归这家公司；你出技术和运营，天俪出品牌、门店和培训 | 长期收益最大，治理最复杂 | 规模化以后，或要把系统卖给其他连锁品牌时 |

**推荐路径**：起步用 B，试点跑通后叠加 C，规模化以后再谈 D。一开始就谈入股，天俪很难接受。

### 3. 按单分成能拿多少（模式 B，每单 ¥3）

| 日均单量 | 对应规模 | 每年分成 |
| --- | --- | --- |
| 50 单 | 试点 3–5 家店 | 约 ¥5.5 万 |
| 200 单 | 约 20 家店 | 约 ¥22 万 |
| 500 单 | 约 50 家店 | 约 ¥55 万 |

- 每单 ¥3 约占集团平台每单净收入（约 ¥24）的 12%。**这笔钱从集团那份里出，不额外向门店收**，否则加盟商会抵触。
- 按单收固定费比按集团收入百分比好对账，订单数清清楚楚。

### 4. 让天俪放心长期绑定

1. **数据归天俪**：客户、订单、技师数据属于天俪，不用于其他客户。
2. **代码交付有保障**：定期交付源代码和文档，或第三方托管，合作结束能找别人接手。
3. **服务承诺写清楚**：可用率、故障响应时间、求助功能故障的处理时限，做不到就扣服务费。
4. **数据透明**：天俪随时看得到订单量和分成明细，按月对账。
5. **约定退出条款**：分成年限、提前终止怎么结算。

### 5. 保护自己

- **设保底**：每年分成不低于某个金额，避免单量起不来时白垫开发成本。
- **代码归属谈清楚**：天俪定制的部分归天俪；通用平台底座归你，授权天俪使用。可以承诺在天俪所在区域或对直接竞品几年内不卖。

### 6. 谈判时怎么说

> "我们不只做外包。首期开发按成本价收，剩下的按订单量从业务增长里慢慢拿回来。你们做得越好，我们赚得越多；做不起来，我们也一起承担损失。系统和数据归你们，代码有备份，不会被我们锁住。"

## 三、运营合作怎么收费

- **基础运营费**：覆盖团队成本。试点期 3–4 人，二线城市约每月 ¥3–5 万；客服和调度由天俪现有客服兼任。
- **超额分成**：只对超过基线的新增订单或新客分成。门店老客迁移来的订单本来就是门店的客户，不算增量，事先说清楚才公平。
- **前提**：试点前先测基线（见方案汇总第六节第 7 条），否则没法算"超额"。
- **考核 KPI**：订单量、新客数、获客成本、30 天复购率、准时率、投诉率、门店活跃率、技师人均单量。
- **责任边界**：安全事件处置的责任主体是天俪，你负责系统监控和第一时间通知。

## 五、你需要先想清楚的

1. **有没有运营团队？** 没有的话，长期价值主要靠技术迭代，模式 C 需要先找合作方或组建团队。
2. **能垫多少资金？** 模式 B 首款打折相当于先垫钱，可能一两年才回本。
3. **要不要把系统做成产品卖给其他连锁品牌？** 想的话，现在就要在架构和合同里给通用底座留空间。
