## 刷新缓存修复（2026-10-11）

用户授权修复首次加载与刷新耗时接近的问题，并继续部署到同一应用。原部署发布 SHA `0f66167eb9a6fd3ca6456efc42469914049ce234` 保留为回退版本。

根因：所有静态资源返回 no-cache，缺少 ETag / Last-Modified 及条件请求处理。实测刷新 105 个资源响应中 104 个为 200、1 个为 favicon 204，无磁盘缓存命中；99 个 JS，传输 867475 字节，首屏内容 1456 ms。首次记录首屏内容 2368 ms。

设计：构建时以发布内容 SHA256 生成版本路径 `/assets/<version>/`，仅改生成的 HTML 的 script / stylesheet 引用；保持业务源码、相对模块依赖、PDF worker、hash 路由和原浏览器数据不变。当前版本路径资源允许一年 immutable 缓存；错误/过期版本拒绝返回新内容。非版本资源及 HTML / release.json 保留 no-cache，补齐内容 ETag、Last-Modified、GET / HEAD 的 304 校验。If-None-Match 优先于日期校验，gzip 使用弱 ETag，避免不同传输表示的强标记冲突。healthz 和错误响应不长期缓存。

验收：普通刷新 JS/CSS 使用浏览器缓存，资源传输量显著低于现状；HTML 可检查更新；改变资源内容会改变版本与 ETag，旧标记获得 200 新内容，旧版本 URL 不映射新内容；五角色和 PDF 相关资源保持可访问，越界/隐藏/文档路径仍拒绝。此次不改业务规则，不新增页面设计，不改变办公室隧道或其他服务配置。
