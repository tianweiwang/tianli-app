## 2. 设计要点

1. **金额和比例**：金额按"分"存整数，比例用万分比（`_bp` 字段），避免小数误差。
2. **快照**：客户归属和分成金额在下单时固定；技师提成规则在接单时固定版本（`tech_rule_version`），改约换了技师的按新技师接单时固定；`rule_snapshot` 存命中的每条规则原文（JSON），门店对账有异议时可以还原当时的计算过程。
3. **防重复预约**：在同一事务里锁住技师行，再检查 `slot_occupancy` 区间重叠后写入（见 02 第 4 节）。预约、改约、加钟都走这一条路径。Redis 只缓存可约时段用于展示。
4. **幂等**：`out_trade_no`、`out_refund_no`、`out_order_no`（分账）、`out_return_no`、`out_bill_no`、`idempotency_key` 都加唯一约束。支付、退款、分账、转账回调重复或乱序到达时，按状态机判断，不重复记账。
5. **状态机**：订单、售后单、退款、分账、提现、佣金、门店、技师的状态变化只能按规定路径走（见 02、04、11、12），非法跳转直接拒绝，每次变化留日志。
6. **数据隔离**：门店账号的所有查询（包括导出）都在服务端强制加 `store_id` 过滤，不依赖前端传参。
7. **加密**：`_enc` 字段加密存储，后台默认只显示部分内容，查看完整信息留日志。
