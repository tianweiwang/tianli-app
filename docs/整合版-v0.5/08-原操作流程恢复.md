# 08 原操作流程恢复

日期：2026-10-02。用户要求：“修复，你不能动咱们原来的操作逻辑，咱们原来的是为主的。”本轮以 `design/prototype-v4` 为基线恢复已认可的操作，保留整合版统一业务数据与商品交易。已完成本轮规则及实际页面核验；核验范围对应 [03 第 8 节](03-场景验收与决策.md#8-恢复原有操作流程用户已授权)的 R01～R07。

## 1. 恢复的用户操作

主路径：**首页 → 片区/门店 → 项目 → 就近或指定技师 → 日期与可约时段 → 联系人 → 首次身份授权与核验演示 → 成年及健康告知 → 确认预约 → 付款结果**。

- 首页继续以预约为主，显示片区、当前门店、项目和附近技师；商城保留独立新增入口。已选门店和项目时，可以沿用原首页快捷入口继续选择技师。
- 片区提供位置使用说明和手动选择；“暂不允许”仍可继续。定位成功只是固定片区演示，未读取设备位置。
- 就近与指定互斥；切门店、项目或偏好后立即清理失效技师和时间。时段按半小时展示总价，不可选项显示休息、请假、占用或时间范围原因。
- 付款前显示具体技师、预约时长、时间和总价，保留修改联系人、技师及时间的入口。正常操作为“确认并支付”，模拟结果选择放在演示设置中。
- 首次身份演示单独同意；成年和健康告知针对实际接受服务的人，支持为家人预约。确认前缺少任一必要信息不能提交。
- 预约详情继续提供支付进度、修改预约、取消金额确认、联系门店、加时、求助和售后等已实现路径。原预约规则与商品主链继续保留。

## 2. 草稿与提交保护

每个标签页通过 `sessionStorage` 按用户 ID 保存预约草稿；业务订单仍在同源共享存储中。返回、刷新和切换角色继续本标签页的本人草稿；用户之间不共用草稿。跨标签业务同步不会用另一标签页的表单覆盖当前草稿。

上游选项变化清理失效的技师和时间，保留联系人。已提交草稿关联原预约；重新发起时创建新的提交标识。撤回身份演示同意会清除核验通过状态。

提交在锁内重新检查可约状态、具体技师和确认页价格。点击时记录当前身份及演示支付结果；等待锁时编辑或另起的草稿不被旧提交覆盖，切换身份或页面后不强制跳回。支付失败保留同一待支付订单，未知结果先查询原笔。

## 3. 候选、时段和排班

用户时段展示、门店派单候选和下单共用 `booking.mjs` 的规则：门店与项目资格、片区覆盖、偏好、工作/休息时间、请假、订单占位和变更占位。尚未选择时间时只判断资格，不以隐含默认时间过滤人员。就近安排按实际可用候选确定具体技师。

工作端恢复预约列表状态/关键词筛选、派单候选与禁选原因、常规排班和指定日期排班编辑。保存排班时，不能排除已有有效预约、待确认变更或加时占位。门店直接派单仍直接确认；指定改派和门店改约仍先等用户决定。

### 已有数据兼容

- 新建演示数据沿用 V4 默认：工作 **09:00–23:00**，休息 **12:00–13:00**。
- 已保存的 schema 5 数据若没有 `schedules` 或某位技师排班，则兼容原整合版 **09:00–23:00、无固定休息**。不重新初始化、不让既有 12 点预约突然失效。
- 第一次保存排班时才补充对应记录；新增休息如与既有有效预约冲突，会提示预约号并拒绝保存。
- 新单要求 `adultConfirmed=true`；旧订单不补造成年确认历史，也不因缺少新字段回退履约或支付状态。

## 4. 接口与数据约定

| 接口 | 用途 |
| --- | --- |
| `bookingOptions(s, selection)` | 输入门店、项目、片区、模式、偏好、指定技师及可选时间；返回门店覆盖/距离、各技师可用性/原因、实际候选、价格和时长。传已有预约 ID 时排除自身占位；原时段派单不误套新预约提前 2 小时限制。 |
| `bookingSlots(s, selection, date)` | 返回当天半小时网格，每项含 `startAt/time/priceCents/available/techId/reason`；新预约至少提前 2 小时、最远 7 天，并能在工作时间内完成。 |
| `bookingSchedule(s, techId, date?)` | 读取生效排班；指定日期覆盖优先，缺记录时返回兼容默认。纯查询不会写入业务数据。 |
| `booking.schedule-save` | `{techId?,start,end,breakStart,breakEnd,date?}`；时间为 `HH:mm`，休息两端可同时留空；日期为 `YYYY-MM-DD`，省略为常规排班。本人、本店店长/门店或集团可操作，仍由规则层验权与冲突校验。 |
| `booking.create` | 新增必需 `adultConfirmed`，原 `identityVerified/healthConsent` 检查保留；UI 草稿另要求 `identityConsent`，不收集真实身份凭证。 |

排班保存于 `state.schedules[techId]`：`{start,end,breakStart,breakEnd,dates:{日期:{start,end,breakStart,breakEnd}}}`，并保留更新时间与操作记录。完整接口与模块约定见 [DESIGN.md](../../design/integrated-v5/DESIGN.md)。
