## 2. 实际使用者与检查方法

集团运营要把新商品或项目从建档维护到可销售；仓储需要入库、核对占用、出库和盘点；门店负责人要维护营业与人员、处理受影响预约；财务需要核对成功资金、失败任务和票据。用户端应看到这些经营操作产生的正确结果。

每个模块都核对：**资料从哪里创建 → 谁能修改 → 什么状态能操作 → 会影响哪些新旧业务 → 失败如何继续 → 操作和资金如何留痕**。不能依赖修改代码或预置记录来完成正常经营动作。

## 4. 商品管理具体做到哪里

### 4.1 集团操作页面

| 商品详情和变更记录 | 各规格、图文、当前规则、操作人/时间/原因、历史版本 | 查询历史版本不会改变当前销售配置；不能用物理删除抹掉有历史订单的商品 |

运营在页面管理“商品”，仓储在页面管理“库存”。上架商品不等于已入库，库存编辑不能混在普通商品资料保存中无记录地覆盖。

### 4.2 库存操作

- 按规格查看实物、待支付占用、已付待出库占用、可售数量；点占用可定位订单。
- 入库填写数量、来源/原因和凭证说明，保存产生入库单与流水。重复提交不能重复增加。
- 盘点记录账面值、实盘值、差异和原因；确认调整生成新流水，保留原记录。
- 盘亏或报损后数量若小于有效订单占用，先进入缺货协调，不能产生负可售数或静默取消订单。
- 退货通过已有验收决定可售入库或报损，同一退货不能再被手工重复入库。

### 4.3 必须联动验证的场景

1. **从空白新建商品**：集团填资料/规格 → 存草稿，用户不可见 → 入库 → 发布 → 用户搜索、选规格、加购、付款 → 集团发货 → 用户收货。全程不改源码或注入业务数据。
2. **加购后调价**：用户看到变化并重新确认，不能静默按新价扣款；已生成订单保持原价格、名称和佣金快照。
3. **下架后继续历史单**：商城停止新购买，购物车明确失效；已付单仍能查看、发货或按售后规则退款。
4. **最后一件和盘点**：库存被有效订单占用后，另一单及盘亏调整不能抢走已承诺库存；未付关闭只释放一次。
5. **改佣金及停推广**：新订单使用生效规则和有效来源，历史订单来源/佣金版本保持；已付佣金退款后仍产生相应追回。
6. **改商品名称**：规格仍属于同一商品，不与重名商品混合；历史订单按下单快照展示。
7. **权限**：门店推广者不能改集团价格、库存和商品退款；集团仓储不能以出库权限修改佣金规则。
8. **失败和误操作**：保存校验失败保留草稿，取消编辑不生效；重复提交、刷新和多标签同时变更须显示实际保存结果及冲突。

## 5. 建议实施顺序与完成条件

### 第一批：基础管理能产生真实业务

恢复旧后台项目/价格与规则操作；补商品档案、分类/规格、上下架、入库/盘点与变更日志。接回门店资料、技师档案及审核，以同一门店/技师/项目 ID 接入既有预约。

完成条件：运营能从空白建一项商品、维护一个预约项目；仓储有来路可查的库存；新建资料真正出现在既有用户流程；商品改动保护历史单；预约入口顺序和已确认规则保持。

### 第二批：组织及异常处理有出口

门店暂停/停推广/关闭，技师停单/调店/离职，用户限制/解除，商品改址/按行取消/物流及退货超时待办。补齐相关细分岗位演示权限。

完成条件：每次经营状态改变都能先看影响清单，逐笔处理在途业务，历史履约事实和资金记录不消失。

### 第三批：原财务、发票和经营查询接回

迁移服务财务、提成、个人推广/提现、服务发票；补商品发票、报表钻取、组合筛选、导出和差异待办。复用原交互与规则，补原后台自身尚未完成的细节。

完成条件：从具体订单能追到实际支付、退款、分账/佣金、发票和责任人；每张报表能回到明细。原需求中仍待定的费用、时限、首单资格等保持独立待决，不靠演示默认值定案。

三批均属于完整经营 Demo 的补齐工作；批次是实施顺序。现阶段继续明确本地模拟与真实认证、渠道、消息、附件和真机验收的区别。
