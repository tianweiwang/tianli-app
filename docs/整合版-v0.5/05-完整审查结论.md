## 3. 第二轮新增问题

### P1 · OLD-15 非分销顾客可动用另一人的佣金

- **触发**：切李四→直达 `/distribution`→页面仍显示陈女士DST1001→输入1元和虚构收款标识→提交模拟提现。
- **实际**：陈女士可提现余额117.40降为116.40；李四也能在分享页生成署名陈女士的推广。隐藏入口并没有限制读写权限。
- **根因**：[Distribution-CYBKVDzn.js:1](../../design/reference-demos/franchise-demo/assets/Distribution-CYBKVDzn.js:1) 的 `overview/withdraw` 使用固定 `state.distributor`；[主包:114](../../design/reference-demos/franchise-demo/assets/index-CaL3mImg.js:114) `R3`（944310）、`lB`（989871）、`aB`（987351）未按当前顾客验证分销身份。偏移为JS字符索引。
- **修正/验收**：分销档案按当前用户查找；列表、分享、申请提现统一校验身份与权益所有者。非分销用户直接链接也不能读取或更改他人资产。此项与OLD-02“接受推广串号”根因不同，须分别修。
- **证据**：[李四身份下提交陈女士佣金提现](verification/round2/customer-cross-account-withdrawal.png)。仅本地模拟，无真实转账。
- **独立复核**：主审在4190切李四后提交1元，陈女士余额127.40→126.40；[同屏截图](verification/round2/boundary-cross-account-withdrawal.png)同时显示李四选中、陈女士档案和扣后余额。两次隔离数据起始余额不同，不是同一笔提现。

### P2 · OLD-16 购物车跨顾客共用

- **触发**：陈女士加2件修复液→切李四→购物车仍有这2件→李四模拟支付796元。
- **根因**：[cart-BTpTOt_f.js:1](../../design/reference-demos/franchise-demo/assets/cart-BTpTOt_f.js:1) 使用单一 `cart`，只按商品/规格找行；主包 `Bj` 切顾客不切购物车。
- **影响/验收**：顾客看到并可能误买他人的选购内容。按customerId保存购物车与结账草稿；切账号不迁移，切回能恢复本人内容。[截图](verification/round2/customer-cart-cross-account.png)。

### P2 · OLD-17 首页搜索无法进入有效搜索

- **触发**：点击“搜索服务与商品”。
- **实际**：跳到 `category=[object PointerEvent]`，标题同值、显示0商品，也没有搜索输入。
- **根因**：[Home-CnBx5IFW.js:1](../../design/reference-demos/franchise-demo/assets/Home-CnBx5IFW.js:1) `on.click=openCategory`，把点击事件传给分类参数；[Category-DPaIoqrG.js:1](../../design/reference-demos/franchise-demo/assets/Category-DPaIoqrG.js:1) 初始读取参数时接受了该值。
- **验收**：搜索进入可输入及清空条件的搜索页；分类入口只传合法分类，无结果时能改条件。[截图](verification/round2/customer-search-event.png)。

### P2 · OLD-18 已取消预约的成功页仍让用户赴约

- **触发**：创建BK2017并取消，再打开它的 `booking-success` 地址。
- **实际**：仍显示“预约成功／请按预约时间前往”及826117二维码；详情页则显示已取消、核销码停止使用。
- **根因**：[BookingSuccess-Dj-v0cWE.js:1](../../design/reference-demos/franchise-demo/assets/BookingSuccess-Dj-v0cWE.js:1) 仅判断记录存在，未判断状态。
- **验收**：成功页重访读取当前事实，取消/过期明确提示且不显示有效外观核销码；有效预约的所有者校验另由OLD-01处理。已取消码在核销动作端会被拒绝，不能误称取消后还能实际核销。

### P2 · OLD-19 分享标签与二维码指向不一致

- **触发**：生成“精选商品”TL-SH-1005→切换“预约到店”模板而不重新生成→打开现有链接。
- **实际**：二维码标签变成预约，链接仍是1005，落地仍为精选商品。
- **根因**：[Share-DDSKJhx4.js:1](../../design/reference-demos/franchise-demo/assets/Share-DDSKJhx4.js:1) `selectedId` 变化没有清空 `generatedShareId`；标签读取当前selected，二维码读取旧generatedShare。
- **验收**：切模板先清除旧码或明确保持原已生成对象；标题、码、复制链接、落地内容和锁定来源一致。

### P2 · OLD-20 无效或不可访问订单缺少错误出口

- **触发**：订单详情、预约详情、付款成功、预约成功四类地址传不存在的ID；另验他人商品订单。
- **实际**：主体空白，只剩全局导航，无不存在/无权说明。商品详情对他人订单的保护有效，错误反馈缺失。
- **根因**：[OrderDetail-C0W-_zGn.js:1](../../design/reference-demos/franchise-demo/assets/OrderDetail-C0W-_zGn.js:1)、[BookingDetail-mfb9_rv4.js:1](../../design/reference-demos/franchise-demo/assets/BookingDetail-mfb9_rv4.js:1)、[PaymentSuccess-6XPsZhiZ.js:1](../../design/reference-demos/franchise-demo/assets/PaymentSuccess-6XPsZhiZ.js:1)、`BookingSuccess-Dj-v0cWE.js:1` 条件不满足时渲染空节点。
- **验收**：显示不泄露他人信息的不可访问提示，提供返回本人列表入口。已有商品、服务、报告、直播和分享的错误状态可作为样式参考。

### P2 · OLD-21 标准服务被显示为定制报价

- **触发**：集团新增标准定价的单次服务，不填写疗程；保存后查看列表和详情，再编辑。
- **实际**：列表显示“到店定制”，详情写“到店评估后定制报价”，编辑仍显示标准定价。
- **根因**：[Products-i1klWqNW.js:1](../../design/reference-demos/franchise-demo/assets/Products-i1klWqNW.js:1) 用 `packagePriceCents` 是否有值决定报价文案，没有读取 `priceModel`。
- **验收**：单次标准价、疗程价、定制价分别按保存模式展示，缺疗程不改变单次定价模式。整合预约沿用当前一口价规则。[截图](verification/round2/brand-standard-service-quote.png)。

### P3 · OLD-22 全部项目计数错误

- **触发**：消费者服务分类显示“全部项目0”，列表实际31项，具体系列计数正常。
- **根因**：[Category-DPaIoqrG.js:1](../../design/reference-demos/franchise-demo/assets/Category-DPaIoqrG.js:1) `seriesCounts` 只按系列累计，模板查“全部项目”键得到默认0。
- **验收**：总数等于当前门店可见服务数量，分类计数与筛选后列表一致。

### P3 · OLD-23 结算优惠标签未随客户身份变化

- **触发**：李四创建并核销198元预约，查看本金/积分不足的结算面板。
- **实际**：本金来源固定标“会员6.6折”，同一行待扣金额及底部“实扣”却为198元。当前结算被余额校验禁用，未发生扣款；这是优惠说明与计算结果矛盾，不是误扣款证据。
- **根因**：[MemberSettlementPanel-DB4x-qp7.js:1](../../design/reference-demos/franchise-demo/assets/MemberSettlementPanel-DB4x-qp7.js:1) 的静态模板写死折扣标签，金额通过 `principalPricing` 按当前客户计算。
- **验收**：标签、原价、优惠和待扣金额由同一份当前定价结果生成；普通客户显示原价，会员展示实际适用折扣。核销页和预约详情复用组件须一致。[浏览器证据](verification/round2/store-insufficient-balance.png)。

## 5. 已确认有效的保护及修正过的判断

- 商品订单列表、详情、付款成功页和检测报告具有顾客隔离；预约相关页面没有同等保护。
- 核销会拒绝取消、过期、重复、跨店、无效码。图片识别已在IAB补验有效和无二维码图片两种结果。
- 会员结算检查门店、核销状态和余额；重复确认不重复扣款。补验积分1780扣198后剩1582，本金不变；另一顾客本金0、积分100时，198元结算在核销页及预约详情均被禁用。
- **核销页刷新后本页结算入口消失，但预约详情能够补结算。** 已实测本金5100扣130.68变4969.32，再点不重复扣；因此不将其列为闭环阻断。见 [证据](verification/round2/store-settlement-restored.png)。
- 直播可从新建到开播再结束；消费者购货/预约入口需接到统一链，不能另建来源和资金规则。
- 新商品首单可以触发旧推荐奖励8元与待结佣金31.84元；这只证明旧正向奖励能发生，退款回收没有闭环，也不代表采用该费率。
