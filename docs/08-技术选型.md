# 08 技术选型

推荐 uni-app + Spring Boot + MySQL，部署在腾讯云：和微信生态对接最顺，国内也最容易招到人。后端语言可以按团队熟悉程度换成 Go 或 Node。

| 层 | 推荐 | 理由 |
| --- | --- | --- |
| 小程序 | uni-app（Vue 3 + TypeScript） | 用户端和技师端一套代码；以后技师端需要 App 时可以直接编译 |
| 后台前端 | Vue 3 + Element Plus | 和小程序同一技术栈，后台组件成熟 |
| 后端 | Java + Spring Boot 3 | 微信支付官方 Java SDK（wechatpay-java）支持 APIv3 服务商、分账、商家转账；资金类系统常用 |
| 数据库 | MySQL 8 | 业务和资金数据；防重复预约和幂等都靠事务、行锁和唯一约束保证 |
| 缓存 | Redis | 可约时段展示缓存、限流；不作为能否预约的判断依据 |
| 定时任务 | XXL-JOB | 超时关单、派单超期退款、售后期满分账、分账重试、强制分账、告警、佣金结算、保单到期停接单；有可视化的执行记录 |
| 支付 | 微信支付服务商模式 + 分账 + 商家转账 | 门店子商户收款、分账给集团、分账回退、佣金付给分销员 |
| 地图 | 腾讯位置服务 | 小程序自带的地图就是腾讯地图；地址解析、距离计算、导航 |
| 虚拟号码 | 阿里云或腾讯云号码隐私保护 | 用户和技师互相看不到真实号码 |
| 实名 | 实名核验（二要素）+ 腾讯云人脸核身 | 用户下单前二要素核验；技师入驻做人脸核身 |
| 求助通知 | 语音外呼 + 短信 + 微信订阅消息 | 求助必须能打电话叫醒值班人员，不能只靠消息推送 |
| 客服 | 微信客服 + 客服电话 | 小程序内"联系客服"；订单问题先转门店，再转集团 |
| 文件 | 腾讯云 COS | 技师照片、证书图片、售后凭证图片、电子发票 |
| 部署 | 腾讯云 + Docker | 和微信服务都在腾讯云；小程序和域名要先完成备案 |

## 资金相关的实现要求

- 所有微信回调（支付、退款、分账、转账）都要验签、幂等，并且以主动查询的结果为最终依据。
- 每个定时任务都要能安全地重复执行，执行结果写日志。
- 资金类操作（分账、回退、退款、转账）都有对应的流水表，每天和微信账单对账，差异进入人工处理。
