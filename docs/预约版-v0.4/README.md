# 天俪预约小程序 · v0.4

日期：2026-10-01

本版把小程序收敛为预约入口：用户选择区域、门店、项目、技师和时间，完成付款，再管理预约、改约、改派与退款。实际业务仍是人员提供上门服务；本版没有把业务改成到店服务。

小程序展示预约进度，不展示出发、到达、路程或上门打卡轨迹。界面使用“待确认、已确认、进行中、已完成、客服处理中、已取消”等预约状态，资金状态独立展示。

本轮定位采用模拟坐标或手选片区作为附近匹配基准。片区不等于实际服务地点；详细地点的采集、传递与核验留待正式接入确定，当前原型不声称已验证详细地点或真实GPS。拒绝定位与模拟定位失败均可进入手选片区流程。

## 文档与基线

- [需求说明](需求说明.md)：角色、页面、预约和资金规则、定位用途、原型边界与本版验收条件。
- 原 v0.3 保留不动。付款、派单时限、改约改派、退款、排班请假和门店权限等规则继续承继；本版只按明确的新需求调整小程序呈现与定位方式。
- 配套原型目录：`design/prototype-v4/`。是否完成、通过哪些检查，以该目录的实际验证记录为准。

## 评审时关注

1. 用户能完成选门店、项目、技师、时段、付款，以及后续预约管理。
2. 就近安排与指定技师的区别明确，门店与技师只处理授权范围内的预约。
3. 定位授权有用途说明，拒绝授权仍能手选区域并继续预约。
4. 预约状态与付款、退款状态不会混淆，期限和金额遵循原规则。
5. 全文没有把真实业务描述为到店服务，也没有“审核模式”“上线后切换”等设计。

加载、真实网络失败、并发抢占等通用异常属于正式接入后的验证清单，不把当前有页面或演示按钮等同于这些异常已全部实现。

## 发布前边界

改成预约文案不等于取得审核许可。正式发布仍须按真实服务核验小程序主体、AppID、可用类目、资质、隐私声明与所需接口权限。本版没有核验这些条件，也不承诺微信审核结果。
