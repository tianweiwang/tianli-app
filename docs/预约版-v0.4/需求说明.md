# 天俪预约小程序 · 需求说明 v0.4

日期：2026-10-01

## 1. 目标与适用范围

实际业务仍为人员提供上门服务。小程序承担预约入口与预约管理：选门店、项目、技师、时间，付款并查看预约结果；不展示出发、到达、路程和上门打卡流程。不写成到店服务，不提供审核开关或两套面向审核与实际用户的版本。

本版独立于 v0.3，不覆盖原文件。预约和资金规则承继原基线，新增要求以本版为准；实际服务的安全、实名、健康告知、隐私和资质责任不因界面收敛而消失。

典型用户是希望快速确定时间的成年预约人，可能替家人预约。其主要需求是知道可选门店、项目总价、可约技师和时段，以及付款后谁会确认、发生变化怎么办。没有定位权限或不熟悉地图的用户也要能完成预约。

## 2. 角色与职责

| 角色 | 小程序职责 | 权限边界 |
| --- | --- | --- |
| 用户 | 选区域和门店、选项目和技师、选时段、填写联系信息、付款、查看和管理预约、评价及联系客服 | 仅自己的预约；服务对象可以不同于预约人，继续遵守实名和健康告知要求 |
| 技师 | 查看本人预约、确认或拒绝、开始和完成预约、排班与请假、查看相关收入和说明 | 仅本人获分配的预约；不展示出发/到达操作和持续位置轨迹 |
| 店长 | 本店预约列表、待分配池、分配与改派、发起改约、紧急请假审批、退款与客服待办 | 仅本店数据；不跨店改派已付款预约，不凭界面按钮绕过权限 |

集团的规则配置、财务和客服裁决承继原后台职责。本轮不新增集团小程序角色，不把网页后台全部塞进小程序。

## 4. 用户预约流程

1. 用户授权定位演示，或手选片区。系统用示例坐标展示附近门店和技师距离；不支持的片区给出说明和更换入口。拒绝定位或模拟失败可继续手选片区，真实GPS与接口故障尚未接入。
2. 用户确认一家门店，再选择项目。后续技师与时段限定在这家门店的可用资源内。
3. 用户选择就近安排或指定技师：
   - **就近安排**：付款前确定一位具体技师，按所选门店、项目、片区距离、排班、性别偏好和可用状态筛选；确认页显示“为你安排：技师X”，不等付款后再随意决定。示例位置匹配不代表真实覆盖范围已经验证。
   - **指定技师**：用户主动选定该店可用技师，再查看该技师可约时段。
4. 选择日期和时间。最早可约默认当前时间后2小时，最远可约仍以首次支付时间起7天约束；时段被其他人占用时重新选择。
5. 填写服务对象和联系信息。当前原型只保存匹配片区，尚未采集详细服务地点；正式流程的地点采集与核验时点需要另行确定，不得以片区或门店地址替代实际地点。下单人完成实名，确认服务对象成年并完成健康告知。
6. 确认页清楚列出门店、项目、技师、时段、联系人及总价。提交后锁定时段，15分钟内付款，未付款关闭并释放资源。
7. 支付后显示待确认，并可选择订阅进度消息。用户拒绝订阅不影响预约；真实系统仍按原规则对关键节点提供通知兜底。
8. 技师确认或门店成功分配后显示已确认。开始后显示进行中，完成后显示已完成。用户可从详情处理允许的变更、取消、退款和客服问题。

本轮呈现预约进度，不用到店、到达门店等词语描述实际服务，也不把出发/到达记录改名后继续呈现为行程流程。

## 5. 预约状态与资金状态

### 5.1 预约状态

| 状态 | 含义 | 用户主要操作 | 技师/门店主要操作 |
| --- | --- | --- | --- |
| 待支付 | 已提交，付款期限内保留时段 | 付款、取消 | 查看必要的资源锁定，不作为已付款预约派单 |
| 待确认 | 已付款，等待确认；门店待分配是该状态的子状态 | 免费取消、允许范围内改约、联系客服 | 技师确认/拒绝；门店分配，展示本轮截止 |
| 已确认 | 技师已确认或门店分配完成，预约安排确定 | 允许范围内改约、取消、联系 | 技师开始预约；门店发起改约/改派，不等待重复技师确认 |
| 进行中 | 预约对应的服务已开始 | 联系客服、加时、求助 | 技师完成或发起客服处理；不出现出发、到达按钮 |
| 已完成 | 已记录完成事实和完成时间 | 评价、退款/售后、发票、再次预约 | 查看结果和结算信息 |
| 客服处理中 | 有未解决争议或需核实的问题 | 查看进度、补充说明、联系客服 | 补充说明、处理并记录结果；按原规则暂停结算 |
| 已取消 | 预约已终止 | 查看退款进度、重新预约 | 查看取消原因和资金结果，不恢复为有效预约 |
| 已关闭 | 未支付关闭或支付超时 | 重新预约 | 释放资源，不生成未发生的退款 |

“改派待用户确认”“门店改约待用户确认”用子状态表示，不提前改动原预约事实。对外预约状态可合并原履约状态，但内部操作、退款和审计依据不能因显示文字相同而丢失。

正常完成仍须满预约项目时长及已支付加时总时长；未满时只能按实际原因选择提前结束或客服处理，不能为了收敛页面自动视为已完成。提前结束不自动退款，保留原售后入口和完成时间。

### 5.2 独立资金字段

资金状态至少包括未支付、已支付、退款处理中、部分退款、全额退款、退款待处理、待结算和已结算。取消预约不等于退款已到账；部分退款不等于取消已完成的预约；客服结案不覆盖已退款或已结算结果。

原 v0.3 的资金冻结、分账、回退、佣金、技师提成和发票规则继续适用。用户侧显示实付、退款与净额即可，不把后台已结算当成新的预约步骤。

## 6. 派单、改约与改派

- **首次确认**：技师默认10分钟确认，超时或拒绝转门店待分配。首次派单截止固定为 min（首次支付成功后30分钟，预约开始前60分钟）。门店切换候选、重复操作或重试不延长截止；到期仍未成功分配就自动全额退款。
- **门店分配**：成功后直接已确认，不增加新技师二次确认。所有动作先校验状态、期限、门店与技师可用性。
- **改约**：用户每单默认1次；门店提出的改约需用户确认，不计入用户次数。只能在原门店内、同价且符合可约时间约束；提议或选择时段不提前生效。用户确认新约后开新一轮，截止为 min（确认变更后30分钟，新预约开始前60分钟），由技师重新确认。
- **指定技师改派**：需用户确认，拒绝或确认超时全额退款。默认等待15分钟；尚未完成的首次或改约轮受当前轮截止限制，不能用用户确认延长期限。原预约已确认后再指定改派，用户确认使新轮生效，门店同时完成分配，直接已确认。
- **就近安排改派**：在原门店内替换为符合偏好和资格的可用技师，只通知用户，不要求用户确认；原门店与付款归属不变。
- **被迫重派**：请假、停单或离职只把该技师受影响的已确认且尚未开始相关履约的预约移入待分配；以首次入池时间开启新轮，截止为 min（入池后30分钟，当前预约开始前60分钟）。原系统有实际已出发等事实时也不得回退该预约；这些事实不在本版小程序展示。重复批准不重开期限。
- **请假筛选**：按完整起止日期和时间判断重叠，批准后该时段技师不可分配；无重叠预约、其他技师预约、进行中和已完成预约不变。普通请假仍先处理受影响预约；紧急请假可先批准并自动将符合条件的预约移入池。
- **过期新轮**：开始前60分钟截止已经到达时，不额外给予30分钟。未成功分配的预约立即进入自动退款；晚到的操作不能恢复过期预约。

本版不展示出发/到达阶段，但不得因此承诺所有已确认预约永远免费取消或无限制改约。真实业务发生的成本或已经开始履约，会影响原规则允许的操作；需要扣费时先显示具体金额、原因及退款净额，不能只依赖小程序可见的预约状态推算。真实履约事实与取消依据的后台记录、告知及权限需在正式接入时核验。

## 8. 定位与隐私

- 定位仅用于本次片区识别、附近门店距离推荐与就近技师匹配。先说明用途，用户主动点击后再申请；不为看首页或查看已有预约强制索取定位。
- 当前定位演示使用固定的示例坐标。拒绝与模拟失败共用手选片区流程，选择后按该片区的示例位置继续匹配；真实接口拒绝或获取失败时的检测、重试与错误分类待接入验证。
- 不展示技师实时轨迹，不持续收集后台位置。片区选择仅保存附近匹配所需的信息；本轮没有详细服务地点输入或覆盖校验，不声称已经确认实际服务可达性。
- 片区和手机当前位置均不能直接认定为实际服务地点。详细地点采集、传递、确认与覆盖核验列入正式接入待定事项；确定后按既有权限和保留规则处理。改变片区/门店时需要重新校验项目、技师、时段与价格。
- 真实小程序的定位和相关接口接入须按正式AppID及当前平台要求核验权限与隐私配置。v0.4本地原型的定位为模拟数据和交互分支，不读取真实微信定位，不证明真实GPS、定位精度或权限可用。
