# 09 验收用例

一期交付必须通过下面全部场景；资金类用例的金额按 [03 第 9 节](03-资金与结算.md) 的样例比例核对，每个场景都要算平到分。本文件是验收要求，浏览器原型演示通过不代表真实支付、并发、微信真机或生产验收通过。

## 预约与履约

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| Y1 | 两个用户同时预约同一位技师的重叠时段（包括一个指定、一个就近安排） | 只有一个能锁定成功，另一个提示时段已被占用 |
| Y2 | 加钟请求和下一位用户的预约同时竞争同一段时间 | 只有一方成功，技师的占用区间不重叠 |
| Y3 | 用户锁定时段后不付款 | 15 分钟后订单关闭，时段释放，别人可以预约 |
| Y4 | 支付回调晚于超时关单到达，时段仍空闲 | 订单恢复为待接单，时段重新占用 |
| Y5 | 支付回调晚于超时关单到达，时段已被他人占用 | 自动全额退款并通知用户，不出现两单重叠 |
| Y6 | 技师 10 分钟内没确认接单 | 订单进入门店待派单池，店长收到提醒；技师之后再点接单，提示已超时 |
| Y7 | 首次支付后门店多次切换候选、重试派单，但到固定派单期限仍未派单成功 | 期限始终为首次支付后 30 分钟与开始前 60 分钟的较早者；到期自动全额退款，通知用户和店长；晚到的派单请求不能恢复订单 |
| Y8 | 指定技师的订单被店内改派，用户拒绝或到确认截止仍未确认 | 全额退款，原技师和新技师的时段都释放；确认默认15分钟，尚未完成的派单轮须受当前轮截止限制 |
| Y9 | 尝试把已付款订单改派到其他门店 | 系统拒绝 |
| Y10 | 技师出发后用户取消 | 取消前弹窗显示扣费金额；退 80%，扣费按集团抽成和技师补偿分配，金额与样例 D 一致 |
| Y11 | 用户约最早可约的时段并付款 | 技师有 10 分钟确认、门店有剩余时间派单，不会马上被自动退款 |
| Y12 | 用户改约时选不同价的时段、选超过"支付时间 + 7 天"的时段、改约次数已用完、技师已出发 | 不同价和超期的时段不可选；次数用完或已出发时改约入口不可用，并说明原因 |
| Y13 | 用户确认改约成功，或确认门店提出的新约 | 原时段释放、新时段占用，在同一事务内完成；订单回到待接单，由技师重新确认；新轮到期为确认时间+30分钟与新开始前60分钟的较早者，候选变更不延长；首次支付时间及资金期限不变；确认前不变更原约 |
| Y14 | 技师开始前 30 分钟没出发；开始时还没出发；最后联系不上 | 依次提醒技师和店长、店长告警；按技师爽约处理，全额退款并记入技师考核 |
| Y15 | 技师中止服务，核实为用户原因 | 订单进入客服介入、暂停分账；判定后不退款，技师提成按完成计算，用户被拉黑 |
| Y16 | 用户要求提前结束服务 | 订单正常完成，不自动退款，用户可以在售后期内申请售后 |
| Y17 | 门店设置暂停营业 | 停业时段内门店不参与匹配；已有订单显示在受影响列表，需门店改约（用户确认）或取消并全额退款 |
| Y18 | 技师当天紧急请假获批，其名下同时有未出发、已出发、服务中和已完成订单 | 仅该技师受请假影响的已接单且未出发订单进入待派单池，店长收到提醒；已出发、已到达、服务中、已完成及其他技师订单保持原状态 |
| Y19 | 未服务满预约时长，或已付加钟使总时长增加后尝试正常完成 | 未满时长不能正常完成，提示剩余时长；满预约及已付加钟时长后才可完成；选择用户要求提前结束可完成且不自动退款 |
| Y20 | 门店在当前派单期限内成功派单 | 直接进入已接单，通知技师和用户，无需技师二次确认；指定技师改派先完成用户确认，不绕过确认规则 |
| Y21 | 尚未派单成功时多次发起指定改派；已接单后因紧急请假被迫重派；已接单后用户确认指定改派 | 未完成轮的确认截止不超过当前轮，确认不能延长期限；被迫重派以首次入池时间开新轮，重复审批不重开；已接单后的指定改派确认使新轮生效且门店同时派单完成，直接已接单；若开始前60分钟已到，尚未派出的新轮立即退款 |
| Y22 | 肩颈项目选择日间、21:00夜间时段，或支付后改到不同价时段 | 默认显示198元/228元，时段价按预约开始时间判定；集团改价不改变已提交订单的价格快照；已支付订单不同价改约不可选 |

## 资金与结算

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| Z1 | 支付、退款、分账、转账的回调重复或乱序到达 | 不重复记账，状态不倒退 |
| Z2 | 同店门店客户、集团客户、跨店三种订单完成后分账 | 分账金额、门店到账、佣金分别与样例 A、B、C 一致 |
| Z3 | 售后单处理中时售后期满 | 不分账，佣金保持"待结算"；售后单关闭后立即分账 |
| Z4 | 售后阻断一直持续到 T0 + 25 天 | 按扣除已确认退款后的金额强制分账并完结 |
| Z5 | 分账接口连续失败 | 按间隔重试 5 次后转人工；T0 + 27 天还没成功，通知集团财务 |
| Z6 | 分账前部分退款 98 元 | 金额与样例 E 一致；技师提成按比例减少（门店设成"不减少"时不减少） |
| Z7 | 分账后退款 98 元，佣金还没提现 | 金额与样例 F 一致；先退款，后回退 14.70 元 |
| Z8 | 分账后退款，佣金已经提现 | 抽成差额立即回退；佣金差额记为分销员负余额；扣回后再回退给门店 |
| Z9 | 退款时门店余额不够 | 订单标记"退款待垫付"，通知店长和集团财务，生成追偿台账记录；门店充值后自动重试 |
| Z10 | 修改抽成、佣金、技师提成规则后 | 已下订单的分成金额不变；已接订单的技师提成不变 |
| Z11 | 保存一条"集团抽成 + 门店出的佣金"超过 30% 的规则 | 保存被拒，提示原因 |
| Z12 | 分销员重复点提现、或同时发起两笔提现 | 同一笔佣金只能提一次 |
| Z13 | 转账失败或被撤销 | 佣金恢复"可提现"，记录原因；转账接口受理成功但还没到账时不显示"已到账" |
| Z14 | 门店 24 小时没处理售后；集团裁决退款 | 售后自动转集团；裁决后系统自动执行退款并调整分成 |
| Z15 | 已结算订单在服务完成后 30 天内由客服特批退款 | 走分账后退款流程：先退款，再回退，必要时记入追偿台账 |
| Z16 | 中止服务判定不是用户原因 | 按没服务的时长比例部分退款，分成和技师提成按比例调整 |
| Z17 | 已开发票的订单发生退款 | 发票标记"待红冲"，门店红冲后可以按新金额重开 |
| Z18 | 主单申请退 98 元、加钟申请退 49 元，协商退 100 元；其中一笔退款失败后重试 | 主单退 66.67 元、加钟退 33.33 元；总额等于 100 元且每笔不超申请额；重试保持原分笔金额，已成功的支付不重复退款；分成和发票按各笔实际退款调整 |
| Z19 | 同一分销员在一个Asia/Shanghai自然日创建3笔提现，结果含失败或撤销；再发起第4笔，并检查重复请求、前置失败与跨日 | 成功创建的前3笔均占次数，失败/撤销恢复余额但不恢复次数，第4笔被拒；同笔幂等重复和未成功创建的前置失败不计；次日计数归零，旧申请余额锁定不受影响 |

## 权限与安全

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A1 | 门店账号通过接口或导出，尝试读取其他门店的订单、客户、对账数据 | 全部拒绝，留访问日志 |
| A2 | 求助通知的某个渠道失败、3 分钟没人确认、定位失败 | 自动重试并通知下一位值班人；按规则升级到集团安全负责人；全部无人响应时提示拨打 110；每一步都有记录 |
| A3 | 技师保单到期；用户没实名就下单 | 技师不能接单；用户不能下单 |
| A4 | 没勾选健康告知，或勾选时服务对象未满 18 周岁 | 不能提交订单 |
| A5 | 被拉黑或限制下单的用户打开小程序下单 | 不能下单，显示原因类别、到期日和申诉入口 |
| A6 | 差评申诉成立 | 评价隐藏，不再计入技师评分 |
| A7 | 用户拒绝订阅消息 | 技师接单、出发、退款等关键节点收到短信 |
| A8 | 分销员查看推广中心 | 只能看到绑定客户数和佣金，看不到客户的手机号和地址 |
| A9 | 服务中发起求助，3 分钟后升级，再过 3 分钟无人确认 | 订单文案始终为客服介入，事件分别显示待接报、已升级、无人响应；分账暂停，110 入口可用，不写回服务中 |
| A10 | 分别在服务未完成、服务已完成和已取消/退款时结案求助，且分别有/无未解争议 | 无争议、未完成时恢复求助前履约状态；仍有争议继续客服或售后处理；保留原完成时间和已终态，不能退回进行中的状态；其他阻断未解除时不恢复分账 |
