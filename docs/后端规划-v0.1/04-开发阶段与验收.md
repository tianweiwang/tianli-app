# 04 开发阶段与验收

## 1. 交付顺序

以下是一期内的开发批次，所有一期模块仍需完成。日历工期要在团队人数、技术栈、第三方账户和首发客户端范围确定后估算；本稿不把外部开通时间计作已经可控的开发时间。

| 阶段 | 交付物 | 可验收结果 | 依赖 |
| --- | --- | --- | --- |
| M0 规划定稿 | 后台首批页面线框、权限矩阵、数据字典、OpenAPI、规则决策记录 | 每个菜单操作能对应服务命令及验收场景 | 首发端、语言、地点/费用事实来源明确 |
| M1 基础与组织 | 工程、登录/权限、审计、门店技师、项目价格、规则版本、排班请假、私有附件 | 本店隔离；具备合格资源；不合格技师不能进入候选 | 数据库和开发环境 |
| M2 预约与收款 | 服务端报价、资源占用、下单、支付、派单轮、后台工作台/列表/详情 | 并发只占一次；技师或门店确认正确；固定期限、晚支付和超期全退 | 实名适配；支付模拟器及真实接入条件 |
| M3 履约与异常 | 改约/改派、加时、开始/完成、取消、请假影响、售后/中止、安全值班及升级 | 主链路与异常可走通；服务事实、时限、退款依据可追溯 | 地点与费用规则；通知适配器 |
| M4 资金与配套 | 分账/完结/回退、对账/追偿、分销/提现、提成、评价/处罚/限制、开票红冲、生命周期收尾 | 金额平衡到分、回调幂等、差异可处理、关停可清算 | 商户实际能力、首单规则、财务初始比例 |
| M5 联调与试点 | 真实供应商接入、真机、并发/故障验证、备份恢复、试点操作手册 | 全部一期验收通过；连续一个实际对账周期无未解释资金差异 | 资质/值班/账号/生产资源就绪 |

开发时先用确定性渠道模拟器覆盖成功、拒绝、超时、重复与乱序；随后用正式允许的测试方式核验真实接口。资金通道未开通时可继续做页面、领域规则、权限和模拟回归，但真实交易验收保持未完成。

## 2. 首批后台设计任务

1. 登录、角色和门店范围；集团/门店工作台。
2. 预约列表、详情、待分配池、候选筛选、分配结果。
3. 改约/改派提案、用户待确认、拒绝/过期以及原约保留。
4. 技师排班、请假审批、受影响预约逐笔处理。
5. 售后列表、案件详情、分笔退款方案、协商版本及执行结果。

设计应同时给出普通列表、空状态、操作已过期、别人已处理、无权限和渠道处理中。后续财务与安全页面也以同一笔预约为入口联查。

## 4. 增补的工程验收

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| B01 | 两个用户、改约与加时同时竞争重叠区间 | 只有合法一方成功，事务回滚不损失原约 |
| B02 | 同一支付/退款/提现通知重复、乱序，处理进程中途退出 | 余额和业务结果只应用一次，重启可续跑 |
| B03 | 门店分配与截止任务同时执行，旧轮请求稍后到达 | 以同一事务锁和服务端时间决定结果，旧轮不能复活订单 |
| B04 | 先正常服务，紧急请假重复批准 | 只影响本人重叠且可重派的预约，原完成/开始事实保持 |
| B05 | 两个客服同时同意退款，同一支付有另一个未完方案 | 总退款及占额不超实付，冲突明确提示，失败重试保留分笔金额 |
| B06 | 请求分账超时、退款结果未知、重试任务崩溃 | 使用原渠道单号查明结果；不会重复分账或错误释放可分金额 |
| B07 | 求助处理中又完成、退款或取消，随后旧结案请求到达 | 保留最新事实；只关闭自身阻断，其他争议继续阻断 |
| B08 | 跨店修改URL、导出、下载附件、提交他店技师ID | 全部按资源归属拒绝；日志可查，无敏感字段泄露 |
| B09 | 提现并发、失败/撤销、跨日、同键异请求 | 余额与每日3次原子校验，结果释放一次，同键异请求拒绝 |
| B10 | 管理员改价、改比例、调整排班及保单到期 | 旧快照保持；新单按有效规则；受影响资源立即不可选 |
| B11 | MySQL恢复备份后重放任务、消息或渠道通知 | 原单号和幂等记录仍有效，差异通过对账发现和处理 |
| B12 | 主单/加时部分退款，已有发票，再次申请和红冲 | 净额、红冲和新票关联完整，累计不超净实付 |
| B13 | 同一用户同时两单、完成顺序反转、首单全退 | 按已确认的首单规则唯一判定，佣金及快照一致 |
| B14 | 门店暂停/关闭、技师调店/离职，已有订单未结束 | 新资源匹配正确，已有订单门店和收款方保持，结清条件可追溯 |

这些场景需在数据库、供应商适配器和真实权限层验证。浏览器原型的170/80个状态及渲染记录作为交互参考，单独保留。

真实主体资质、协议文本、保留期限、个税和财务口径继续按原 docs/10 确认。官方接口文档不能证明某个商户号已开通相应产品。

## 6. 完成标准

每批交付包含实现、数据库迁移、接口契约、页面状态和对应证据。M5正式验收需能从一个订单追溯预约、付款、履约、退款、分成、佣金、提成、发票和通知的完整记录，并解释每个失败或人工待办。

本轮交付完成的是规划材料，工程实施、第三方联调、真机与生产验收按 tasks 保持未完成。
