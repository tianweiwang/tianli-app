## 2. 环境建议

| 环境 | 用途 | 建议配置和边界 |
| --- | --- | --- |
| 本地开发 | 领域规则、数据库迁移、页面和模拟渠道 | 本机运行应用及专用MySQL；使用脱敏/虚构数据 |
| 阿里云联调 | HTTPS接口、后台评审、小程序开发联调 | 保留当前静态原型；轻量API试运行需先测内存，数据库与重型任务控制台优先分离 |
| 试点生产 | 真实收款、预约和安全通知 | 独立应用环境、数据库账号和库、私有对象存储、备份；资源与业务压测后确定 |

初始生产资源可从“应用2核4GB + 独立MySQL/RDS”作为询价和压测起点；这是容量建议，尚未验证可承载的并发量。Redis、任务执行器与应用是否同机，依内存与延迟测试决定。

当前约1.6GB主机承载Java应用、MySQL、Redis及XXL-JOB控制台会缺少余量，建议先用于现有原型和轻量联调。正式环境采用独立数据库与可恢复备份，并评估单应用实例停机时的影响；可用性目标确定后再决定是否增加第二实例。

开发、联调、生产使用独立账号、密钥、数据和通知目标。生产Webhook指向生产适配器；模拟器只接模拟环境配置。

## 3. 发布和恢复

- 前端使用带版本静态目录，API使用固定镜像版本；记录源版本、构建结果、迁移版本和接口版本。
- 数据库变更通过版本迁移执行；先备份、在副本或联调库验证，采用可兼容旧应用的增量变更。
- 新版本通过健康检查及关键链路检查后切换；回滚应用前核对数据库向后兼容性。涉及不可逆数据变更时准备修复迁移，不能假设换回旧镜像就能恢复。
- 外部交易提交后即有真实结果。停机/回滚需要保存任务与幂等记录，重启后按原单号查询；不能清空失败任务后重新生成资金单号。
- 现有 `/tianli/v3/`、`/tianli/v4/` 继续作为评审记录。正式后台与API使用单独路径或域名，绑定方式在工程部署时确定。

## 4. 运维验收建议

以下为待确认的试点目标，不是已实现能力：

| 项目 | 建议目标/方法 |
| --- | --- |
| 备份 | 每日全量、持续或足够频率的增量日志；异地或独立存储留副本 |
| 恢复目标 | 先以RPO≤15分钟、RTO≤2小时估算方案与费用，再通过恢复演练确认 |
| 性能 | 按试点门店、在线人数和预约峰值设负载；分别测查询、占用、回调、批处理延迟 |
| 告警 | 接口错误率、慢请求、连接池、磁盘/内存、到期任务积压、求助无人响应、退款/分账失败、对账差异 |
| 日志 | 请求号关联业务事件、渠道交易和任务；屏蔽凭据、完整身份证/手机号/地址 |
| 密钥 | 独立配置或密钥服务，最小权限，支持轮换；文件不进入代码和公共静态目录 |
| 文件 | 发票/证件/售后凭证私有访问，短期授权下载；公开技师照片使用审核后素材 |
| 操作恢复 | 每次版本发布有回退记录；值班人员能查询交易、处理告警并联系责任人 |

求助3+3分钟升级、派单固定截止等属于业务时限，服务端持久任务和告警共同保障；系统中断后要补处理过期事件并记录延误。

## 5. 费用组成

当前没有已确认的预算、使用量和采购规格，因此本稿列估算口径，不虚构云报价。

| 费用 | 估算方式 | 当前状态 |
| --- | --- | --- |
| 应用主机 | 所选规格、地域、购买周期和带宽 | 现有主机已存在；升级/新增待报价 |
| 数据库 | RDS或独立主机、存储、备份、是否高可用 | 待选型和实际控制台报价 |
| 对象存储 | 文件GB数、请求量、下行流量、备份留存 | COS/OSS二选一后估算 |
| Redis/任务控制台 | 是否托管、内存、单独实例 | 联调可简化，生产按容量决定 |
| 核身、号码保护 | 首次核验人数、技师核身次数、号码绑定/通话量 | 供应商产品和报价待确认 |
| 短信/外呼 | 订单通知数、兜底比例、求助渠道和分钟数 | 按真实业务节点计算 |
| 支付及转账 | 合同费率、实际交易额、获批产品费用 | 以已签商户合同为准 |
| 开发与运维 | 各批工作量×团队人日成本；值班、恢复演练 | 团队和范围锁定后评估 |

月度运行预算 = 固定云资源 + 存储/流量 + 通知/核身/号码用量 + 渠道合同费用。询价需同时提供试点门店数、预计日单量、技师数、文件留存期和峰值并发。

可以先复用当前服务器的剩余资源做联调，新增租金是否为零取决于当前合同和用量；生产资源不能按静态原型的运行成本推算。
