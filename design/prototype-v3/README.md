## 演示方式

1. 用户预约：选择项目、技师、时段，填写实名与服务对象，确认健康告知后支付。
2. 外侧切换“技师”，继续接单、授权位置、出发、到达、开始服务；切回“用户”查看同一笔订单。
3. 技师发起加钟、用户支付；可以演示提前结束、中止核实、售后协商及退款进度。
4. 改约使用拟改数据，确认前保留原预约。新约确认后开启新的派单轮；当前轮尚未派单成功时，指定改派的确认不能延长该轮期限。门店派单成功直接进入“已接单”。
5. “推进时间”检查支付、接单、派单、改派、加钟、售后与求助超时。首次派单截止固定为“首次支付 + 30 分钟”与“预约开始 − 60 分钟”的较早者，换候选或重试不重计。已启动的倒计时也会自然到期。
6. 提现结果按钮模拟渠道的成功、失败、撤销通知；失败与撤销只恢复一次余额，仍占申请创建当天的次数。

演示记录保存在当前标签页的 sessionStorage。刷新可继续；“重置演示”清空这条记录。从首页发起新预约会创建新的演示订单。状态画廊各页使用独立示例，点击后进入对应操作演示。

## 本轮补全

- 用户：地址与服务对象表单、我的、隐私与注销、安全联系人、推广加入、佣金、发票及提现结果。
- 技师：入驻核身、补件与审核、排班请假、爽约核实、客服说明、差评和处罚申诉。
- 店长：告警列表、改派与改约、售后驳回和协商、请假与爽约审批、求助接报和结案。
- 状态：退款执行与结果、求助 3+3 分钟升级、完成后的各期限、加钟失效、限制和通用异常。
- 表单和数据：浏览告知后保留草稿；主单、加钟子单分别退款；发票净额统一；金额与人员资料随订单变化。

## 评审修订

- 派单按轮次记录起点和固定截止；改约生效或已接订单被迫重派才按已确认规则开启新轮。紧急请假仅影响本人、与请假重叠、已接单且未出发的订单，重复审批不重开轮次。
- “正常完成”要求服务满预约时长及已支付加钟时长；未满时可按用户要求提前结束。求助结案保留完成时间和最新终态，有未解争议时继续客服或售后处理。
- 协商退款按各笔申请额比例分配到分，按固定规则补尾差；校验尚可退金额，累计结果幂等。仅反馈或协商总额为 0 时不创建支付退款交易。
- 肩颈默认日间 ¥198、21:00 起夜间 ¥228；每天最多创建 3 笔提现，创建后的失败或撤销仍计次。两项沿用已有默认，已回写需求文档，集团仍可配置。

详细规则和需求出处见 [coverage.md](coverage.md)。改约生效后开启新轮的口径已获用户明确确认。

## 画廊分组

画廊按 **12 个流程组**组织，组内按操作顺序排列：用户端的预约、履约与订单、售后与评价、发票、推广与提现、账户与安全；技师端的入驻与排班、履约、收入与申诉；店长端的派单与订单、告警与审批；通用状态。分组调整不会改变 U / T / S 编号。

## 验证和边界

浏览器验证覆盖全部状态在 320 / 390 / 430 宽度的脚本、跳转目标、操作绑定、横向溢出、控件外框、主按钮尺寸和布局居中。具体实点结果见验证记录。单页图片截取第一屏，长表单与列表可以在原型中滚动。

本轮交付范围为三类小程序端。门店网页后台、集团网页后台仍按 docs/07 留在下一批设计；集团审核、裁决和渠道通知在本原型中使用演示结果。

支付、身份核验、人脸、上传、拨号、通知和转账均为本地演示；未接入后台或在微信真机验收。docs/09 的 **51 条正式验收场景**是实际系统的交付要求，与原型脚本的渲染检查和交互断言分别记录。并发锁、接口权限、分账和回调等仍需要后续实现与集成环境验证。姓名、地址和资质都是示例；业务金额按需求默认参数演示。

视觉沿用白底紧凑列表、分隔线、微软雅黑、品牌色 #C94F35 与告警色 #B42318。健康清单、协议和保留期限继续使用需求草案，定稿事项见 docs/10。

## 重新验证与导出

使用现有 Node、Edge 和 Playwright：

```powershell
node .\design\prototype-v3\verify.cjs
node .\design\prototype-v3\export.cjs 'H:\connextes\edu-plate\node_modules'
```

验证默认连接端口 4183，可用 TIANLI_BASE_URL 调整，实际用例和断言数量以 verification/verification.json 为准。

导出只替换本目录 exports/ 第一层的 PNG；页面目录来自所有脚本加载后的 SCREENS。所有文件名统一过滤 Windows 非法字符，单页保持扁平输出。完整导出应有 **170 张页面 + 12 张总览 = 182 个 PNG、0 个子目录**；总览逐张检查图片成功解码，缺图、重复文件名或目录数量异常会失败退出，结果见 export-report.json。评审发现的 10 个尾空格历史目录已核验并清理。
