- 项目价格与规则快照、门店审核及暂停、名单导入和技师审核、评价、推广、用户限制、账号设置、安全接报与结案。

完整菜单及当前深度见 [coverage.md](coverage.md)，视觉规范见 [DESIGN.md](DESIGN.md)。

## 建议先走的流程

1. **派单**：门店 → 预约与派单 → 王女士的预约 → 分配原技师。直接变为已确认，本轮截止不变。
2. **指定改派**：上述已确认预约 → 店内改派 → 陈师傅 → 演示设置“用户接受”。原安排在确认前保留，接受后开启新轮并完成分配。
3. **改约**：陈先生的预约 → 提出改约 → 填写原因 → 演示设置模拟接受或拒绝。首次支付时间保持；仅接受后改变预约时间。
4. **请假**：技师与排班 → 林师傅紧急请假 → 查看影响并批准。李先生进入派单池，服务中记录保持。陈师傅普通请假须先协调受影响预约。
5. **售后**：售后处理 → AS1001 → 协商100元 → 演示设置接受 → 查询退款选择第二笔失败 → 再次查询全部成功。两笔最终为66.67元、33.33元。
6. **发票**：上述退款后 → 发票FP1002待红冲 → 选择本地凭证 → 登记红冲 → 按347元净额重开。
7. **集团**：右上角切集团 → 分账监控检查阻断；技师档案先通过吴师傅，再到门店管理审核江宁门店上线。

切换流程前可通过演示设置恢复初始数据。初始演示时间固定为2026年10月2日09:40，时间推进用于核验截止与升级；不会随电脑时间自动流逝。

## 启动与复现

已编译样式和图标随原型保存。直接预览只需 Node.js：

```powershell
cd H:\connextes\天俪_app\design\admin-prototype-v1
node serve.cjs
```

修改样式工具类时运行 `npm ci`、`npm run build`。验证时先保持预览服务运行，再运行 `npm run verify`。

验证脚本默认使用本机现有 Playwright 与 Edge。其他电脑可设置环境变量 `PLAYWRIGHT_MODULE`、`BROWSER_PATH`、`PROTOTYPE_URL` 为实际路径和地址，不依赖在线CDN。

## 演示边界

数据保存在当前浏览器的 localStorage；两个端在同一浏览器内共享，跨设备或不同浏览器不自动同步。账号为两个汇总权限的演示身份。文件选择只记录文件名，渠道查询和通知只模拟结果。

服务端认证、细分角色授权、数据库、真实支付/退款/分账、消息发送和附件存储尚未接入。本原型的检查不构成真实渠道或生产验收。业务规划中的关店清算、强制分账日等后续细化页列在覆盖说明中。

本版保存于独立目录，当前仅启动本地预览。此前V3、V4线上版本继续使用原入口。
