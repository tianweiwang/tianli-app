# 天俪预约版 v4

本版独立保存，沿用 v3 的界面风格。用户通过片区定位、选择门店、项目、技师和时间完成预约；技师与店长在同一预约记录上处理确认、变更、完成与售后。

## 打开

在此目录运行 `node serve.cjs`，访问：

- [可操作演示](http://127.0.0.1:4184/demo.html)：切换三类角色、载入情景、推进时间。
- [全部设计稿](http://127.0.0.1:4184/index.html)：按角色和流程查看静态状态。
- `exports/`：单页 PNG 与流程总览，文件全部平铺。

手机画面为 390 × 844；内容区可上下滚动。演示存储使用独立的 sessionStorage，不与 v3 共用。重置演示可从首次预约开始。

## 本版范围

- 首页与片区、门店、项目、就近/指定技师、偏好、可约日期与时间、联系信息、实名与健康告知、支付及预约状态。
- 技师确认、开始、结束、排班和请假；门店安排、改派、改约、请假审批、客服与退款方案。
- 评价、发票、隐私、推广、提现和结果查询。
- 保留完整项目价格、取消依据与分笔退款。已确认预约变更需要用户确认时，原技师与时间保持到确认成功。

三类端统一表达预约状态。没有行程打卡、持续轨迹、审核开关或审核后切换内容。实际业务的类别与责任不会因页面文案改变，不能据此承诺微信审核通过。

## 演示数据与接入边界

定位授权、坐标、门店和技师位置、排班、已占时段及证书均为示例；定位拒绝可手选片区，按本店、项目、偏好、覆盖、时间与距离筛选。片区位置不等于实际服务地点，详细地点采集与传递尚未接入。

微信身份核验、真实定位、支付退款、客服、订阅消息、文件上传、电子票和分享均未接入。演示中的按钮只改变本地记录，不产生真实交易。请使用虚构资料。正式接口、权限、并发锁定、网络异常及真机检查需要后续验证。

`resourceCommitted` 仅演示有明确费用依据时的取消规则，不能根据“已确认”或预约时间直接自动推定扣费。正式系统须核实真实事实和告知依据。

## 文件与验证

| 文件 | 用途 |
| --- | --- |
| `data.js` | 示例门店、技师、价格、距离、资格、排班与占时筛选 |
| `user-pages.js` / `staff-pages.js` | 用户 46、技师 17、店长 17 个状态 |
| `runtime.js` | 同单交互、期限、变更、客服与分笔资金记录 |
| `catalog.js` | 页面编号、流程分组与安全导出文件名 |
| `verify.cjs` | 浏览器三宽渲染与实际按钮、表单交互检查 |
| `export.cjs` | 单页和总览导出、文件清单与图片解码检查 |

运行 `node verify.cjs`、`node export.cjs`。脚本使用本机已有 Edge 和 `H:/connextes/edu-plate/node_modules/playwright`，验证与导出结果保存在本目录。覆盖结论见 [coverage.md](coverage.md)，需求见 [预约版需求说明](../../docs/预约版-v0.4/需求说明.md)。
